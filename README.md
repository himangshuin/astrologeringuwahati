# Important: Generated HTML Architecture

The website follows a **data-driven static-site generation model**.

The generated HTML files should not be manually edited.

The content source is:

```text
data/cities_data.json
```

The site generator is:

```text
scripts/generate.py
```

The workflow is:

```text
cities_data.json
        ↓
   generate.py
        ↓
HTML pages
        ↓
sitemap.xml
robots.txt
```

This makes the website significantly easier to maintain.

For example, adding a new town should normally involve changing the data source rather than manually editing several HTML pages.

---

# Why Use JSON as the Content Source?

`cities_data.json` acts as the central content database for location-specific information.

It can contain information such as:

* District name
* Page title
* SEO title
* Meta description
* Primary keyword
* Secondary keywords
* Local introduction
* Service descriptions
* Towns
* Areas served
* Frequently asked questions
* FAQ answers
* Structured-data information
* Internal-link information

This approach reduces inconsistencies between pages.

For example, instead of manually changing the phone number on 35 pages, the generator can use one common business configuration.

Similarly, a change to a service description can be reflected consistently throughout the generated website.

# Content Guidelines

SEO content should follow several principles.

### 1. Write for people first

Pages should be easy to read and useful to someone actually searching for astrology services.

### 2. Avoid keyword stuffing

Do not repeatedly insert:

```text
Best Astrologer in Guwahati
Best Astrologer in Guwahati
Best Astrologer in Guwahati
```

Instead, use natural variations such as:

* astrologer in Guwahati
* Vedic astrologer
* astrology consultant
* astrology consultation
* astrologer based in Guwahati

### 3. Avoid duplicate location pages

District pages should contain meaningful geographic and service-specific information.

### 4. Avoid doorway-page patterns

Small towns should generally be grouped under appropriate district pages when separate pages would provide little unique value.

### 5. Use descriptive headings

Headings should communicate what the section actually contains.

### 6. Keep FAQs genuinely useful

FAQ questions should reflect real user questions rather than being generated solely to include keywords.

## Robots.txt

The website maintains:

```text

```

at the root of the domain.

This is important because the standard robots.txt location is:

```text
https://yourdomain.com/robots.txt
```

The file can also reference the XML sitemap.

# Canonical URLs

For example, the preferred URL should remain consistent rather than allowing several versions of the same page to compete.

# Important Development Rule

**Never hand-edit generated HTML.**

The following files are generated:

```text
index.html
locations.html
blog.html
blog/*.html
districts/*.html
sitemap.xml
robots.txt
```

If you manually modify them, your changes may disappear the next time:

```bash
python3 scripts/generate.py
```

is executed.

Always modify the source data or generator templates instead.
